# 5. Какие данные мы собираем

## 5.1 Данные учетной записи

При регистрации и использовании учетной записи могут обрабатываться следующие сведения:

* адрес электронной почты;
* криптографический хэш пароля (bcrypt);
* дата регистрации учетной записи;
* внутренний идентификатор пользователя.

Пароль Пользователя никогда не хранится в открытом виде и не может быть восстановлен Оператором.

---

## 5.2 Данные авторизации

Для обеспечения безопасного входа в Приложение могут обрабатываться:

* коды подтверждения;
* дата и время создания кода;
* дата и время окончания срока действия кода;
* JWT Access Token;
* JWT Refresh Token.

Коды подтверждения автоматически удаляются после истечения срока действия либо при создании нового кода подтверждения.

---

## 5.3 Данные устройства

Для обеспечения корректной работы Приложения может использоваться уникальный идентификатор устройства, создаваемый Приложением.

Дополнительно локально на устройстве могут храниться технические сведения, необходимые для функционирования Приложения, включая информацию о версии приложения.

---

Пользователь вправе добровольно указать:

* имя;

Предоставление указанных данных является полностью добровольным.

По желанию Пользователя могут храниться сведения о членах семьи, необходимые для формирования персонализированных рекомендаций.

## 5.6 Данные о покупках

Основной функцией Foodler является обработка информации о покупках Пользователя.

В связи с этим могут храниться:

* дата покупки;
* организация (продавец);
* итоговая сумма покупки;
* перечень приобретенных товаров;
* количество товаров;
* цена товара либо стоимость единицы веса;
* исходная строка QR-кода кассового чека.

Фотографии чеков Оператором не сохраняются.

Изображение используется исключительно для получения информации о покупке и после завершения обработки не хранится Оператором.

---

## 5.7 История использования интеллектуальных функций

Для обеспечения работы функций искусственного интеллекта могут обрабатываться:

* отдельные запросы Пользователя;
* ответы интеллектуального помощника;
* производные представления запросов (например, хэшированные и (или) векторные представления);
* технические данные, необходимые для поиска похожих запросов;
* данные, используемые для кэширования результатов обработки.

Не вся история взаимодействия сохраняется бессрочно.

Часть истории может автоматически удаляться в соответствии с внутренней логикой работы сервиса.

---

## 5.8 Информация о подписке

При использовании платных функций могут храниться:

* статус подписки;
* дата оформления;
* дата окончания;
* информация, необходимая для подтверждения оплаты;
* идентификаторы платежных операций.

Платежные реквизиты банковских карт Оператором не хранятся.

## 5.9 Обращения в службу поддержки

При обращении в службу поддержки могут обрабатываться:

* адрес электронной почты;
* текст обращения;
* вложенные файлы (если они были отправлены Пользователем);
* дата обращения.

В зависимости от содержания запроса это может включать:

История взаимодействия с интеллектуальным помощником может использоваться исключительно для:

* оптимизации внутренних алгоритмов и промптов Foodler.

# 8. Использование сторонних сервисов

Для обеспечения работы отдельных функций Приложение использует сторонние сервисы.

Такие сервисы могут получать только тот объем информации, который необходим для выполнения соответствующей функции.

В настоящее время используются:

* сервис обработки кассовых чеков **ОФД** — для получения информации о содержимом кассовых чеков по QR-коду;
* сервис **Gen-API** — для обработки запросов к сторонним сервисам искусственного интеллекта;
* сервис **ЮKassa** — для обработки платежей и оформления подписки;
* сервис **Gmail** — для отправки кодов подтверждения и обработки обращений пользователей.

Каждый из перечисленных сервисов самостоятельно определяет порядок обработки информации в рамках предоставляемых им услуг.

# 9. Где хранятся данные

Данные Пользователя могут храниться:

* локально на устройстве Пользователя;
* на серверной инфраструктуре Foodler.

Для хранения данных используются локальные базы данных SQLite, а также серверная база данных SQLite.

Часть технических данных может храниться локально исключительно для обеспечения работы Приложения и ускорения доступа к информации.

---

# 10. Срок хранения данных

Срок хранения зависит от типа данных.

Локальные данные на устройстве:

* чеки хранятся до ручного удаления Пользователем, очистки данных Приложения
  либо удаления самого Приложения;
* незакреплённые локальные AI-отчёты автоматически удаляются через 30 дней,
  число локальных отчётов также ограничено.

Серверные данные авторизованных пользователей:

* новый чек без активной подписки хранится до 30 календарных дней;
* новый чек, сохранённый во время активной подписки, не получает автоматического
  срока удаления; окончание подписки не меняет срок уже сохранённого чека;
* данные учетной записи и профиля хранятся до исполнения запроса Пользователя
  на удаление;
* сведения о подписке хранятся в течение срока, необходимого для выполнения договорных и законодательных обязательств;
* история взаимодействия с интеллектуальным помощником может храниться частично и автоматически изменяться в соответствии с внутренними алгоритмами работы сервиса;
* обращения в службу поддержки могут храниться до момента их удаления Оператором.

# 11. Безопасность данных

Оператор принимает разумные организационные и технические меры для защиты информации Пользователей.

В частности:

* используется защищенное соединение HTTPS;
* Первичный сбор, запись, систематизация, накопление и хранение персональных данных граждан Российской Федерации осуществляются с использованием баз данных, расположенных на территории Российской Федерации.
* пароли хранятся исключительно в виде криптографических хэшей bcrypt;
* доступ к данным ограничивается необходимым объемом;
* выполняются резервные копии серверной базы данных.

Несмотря на принимаемые меры безопасности, ни один способ хранения или передачи данных через сеть Интернет не может гарантировать абсолютную защиту информации.

Оператор не гарантирует невозможность несанкционированного доступа третьих лиц при возникновении обстоятельств, находящихся вне разумного контроля Оператора.

# 14. Удаление аккаунта

Пользователь вправе в любое время запросить удаление учетной записи через форму
обратной связи в Приложении либо по электронной почте Оператора. После
подтверждения принадлежности учетной записи начинается процедура удаления
данных Пользователя.

Удаление учетной записи приводит к прекращению доступа ко всем функциям, требующим авторизации.

После удаления аккаунта могут быть удалены:

* сведения профиля;
* история покупок;
* сведения о членах семьи;
* настройки приложения;
* история использования интеллектуальных функций;
* информация о подписке (за исключением сведений, подлежащих хранению в силу закона).

Некоторые сведения могут временно сохраняться в резервных копиях серверной инфраструктуры до их планового обновления либо удаления.
