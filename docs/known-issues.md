# Известные проблемы

Этот документ содержит только незакрытый технический долг. Закрытые проблемы
переносятся в раздел ниже вместе с проверяемой гарантией.

| Приоритет | Область | Наблюдаемая проблема | Условие приёмки |
|---|---|---|---|
| Medium | Mobile profiling | В текущей среде нет подключённого Android-устройства, поэтому release frame trace после оптимизации не записан | На реальном устройстве выполнен сценарий `mobile/PERFORMANCE.md`, бюджеты соблюдены, trace приложен к release |
| Medium | Dev dependency | Полный `npm audit` сообщает один moderate advisory в `@hey-api/openapi-ts@0.97.0`; `0.97.3+` одновременно попадает под более серьёзный advisory parser | Mobile maintainers до 2026-09-01 обновляют/заменяют генератор, когда существует непротиворечивая безопасная версия; до этого используется только доверенный локальный OpenAPI |

## Закрытые mobile-проблемы

На 2026-08-02:

- SQLite-запись чека и позиций транзакционна; mutation публикует batched
  observable-сигнал, поэтому список и статистика обновляются без повторного
  входа. Серверный batch вызывает одно перечитывание.
- Список чеков и позиции большого чека виртуализированы. Удалены
  render-time `Animated.Value` и неиспользуемые JS `onScroll`; tab/progress
  animations используют native driver.
- Дублирующая форма ручного чека удалена, а создание/валидация вынесены в
  `features/receipts`. Выбранная дата, цена, количество и копеечное округление
  покрыты behavior-тестами.
- Синхронизация больше не помечает неуспешную загрузку завершённой и не
  запускается повторно из экрана login. Персистентная очередь удалений не даёт
  удалённому офлайн чеку вернуться из server pull.
- Сетевая ошибка получения AI-кредитов показывается отдельным состоянием с
  retry и не маскируется под исчерпанный баланс.
- Семейный AI-контекст передаёт корректные рост, вес, пол и предпочтения;
  AI/QR/profile payload не выводятся в console.
- Из lockfile удалены 500+ неиспользуемых пакетов и все critical/high
  advisory production-графа. `npm audit --omit=dev` возвращает 0, проверка
  добавлена в CI; lint проходит без warnings.

## Закрытые backend-проблемы

На 2026-08-02:

- YooKassa webhook сверяет платеж повторным запросом к YooKassa, проверяет ID,
  статус, `paid`, сумму, валюту и владельца, а подписку продлевает
  идемпотентно.
- LOCAL actions имеют единственный маршрут, не загружают LLM-контекст, не
  вызывают провайдера и не создают credit usage.
- Credits возвращаются типизированно; стоимость `ask` равна 2; конкурентное
  списание ограничено атомарным balance-бакетом и отдельной миграцией.
- Все HTTP-запросы и безопасные доменные события пишутся в JSON с request ID.
  Email, токены, QR/receipt payload и AI-контекст не логируются.
- Backend-тесты имеют timeout, запрещают внешние TCP-соединения и полностью
  завершаются в CI без `skip`/`xfail`.
- Дублирующий legacy AI route удалён; YooKassa вынесена в integration adapter,
  обработка подписки — в application service.
- JWT имеет issuer/audience/type/version, refresh tokens и email-коды
  хешируются, смена пароля отзывает все сессии, CORS использует allowlist.
- Rate limiting хранится в общей БД и работает между несколькими workers.
- `Subscription` является единственным источником entitlement, YooKassa —
  единственным платёжным провайдером.
- Денежные значения хранятся целыми копейками, даты типизированы, миграция
  проверена переходом с предыдущей revision.
- Списки чеков пагинированы, mobile выгружает все страницы; аналитика агрегирует
  расходы в SQL, product matching ограничивает число кандидатов, N+1 устранены.
- Общий HTTP pool применяется к aiohttp-интеграциям; SMTP и YooKassa имеют
  собственные клиенты. Все внешние вызовы имеют timeout и adapter seam.
- Добавлены `/ready`, защищённые `/metrics`, фоновый retention и bounded
  нагрузочный smoke-тест.
