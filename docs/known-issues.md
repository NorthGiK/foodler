# Известные проблемы

Этот документ фиксирует исходный технический долг. Он не заменяет issue tracker:
при начале работы каждый пункт переносится в отдельную задачу с тестом
воспроизведения.

| Приоритет | Область | Наблюдаемая проблема | Условие приёмки |
|---|---|---|---|
| Critical | YooKassa | Webhook route возвращает 404, проверка события отключена | Недоверенные события отклоняются; валидное событие проверяется через YooKassa и обрабатывается идемпотентно |
| Critical | AI LOCAL | Локальная обработка и маршрутизация реализованы неоднозначно | LOCAL actions не вызывают LLM, возвращают типизированные секции и не списывают credits |
| Critical | Credits | Клиент и сервер расходятся в получении доступного лимита | Авторизованный typed-запрос показывает серверные `remaining` и `period_limit`; списание атомарно |
| High | Backend | Нет единого рабочего структурированного логирования | Request ID и безопасные события доступны в JSON-логах без секретов и персональных payload |
| High | Tests | Полный backend suite зависает после начала выполнения | Все тесты завершаются в CI, внешняя сеть запрещена, зависания ограничены timeout |
| High | Mobile state | Локальные изменения иногда видны только после повторного входа | Mutation обновляет observable state и текущий экран немедленно |
| High | Mobile performance | Навигация и списки работают с лагами, анимации непоследовательны | Профилирование задаёт бюджет кадров; длинные списки виртуализированы; анимации не блокируют JS |
| Medium | Structure | Повторяющийся код и крупные модули затрудняют изменения | Рефакторинг выполняется по измеримым seams после покрытия behavior-тестами |
| High | Dependencies | `npm audit` исходного lockfile сообщает 44 уязвимости, включая одну critical в транзитивном дереве | Каждая цепочка атрибутирована; безопасные обновления применены без `--force`; исключения имеют владельца и срок |
